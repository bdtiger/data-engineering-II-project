The deployed system uses two OpenStack VMs: a development VM for training and model selection, and a production VM that serves predictions via Flask and Celery workers; a Client VM is used only as the control node for provisioning and Ansible orchestration.

\subsection{Infrastructure and Data Collection}

We provisioned both VMs (Ubuntu 22.04, ssc.medium: 2 vCPU, 4 GB RAM, 20 GB disk) using the OpenStack API and automated VM configuration with Ansible~\cite{armstrong2015}. We collected 2{,}000 GitHub repositories ($\geq 50$ stars) via the authenticated GitHub API with rate-limit handling. From the raw 15 fields returned, we selected 11 features: 6 activity indicators (forks, subscribers, issues, size, network count, age in days), 3 binary flags (wiki, pages, issues enabled), and 2 diversity indicators (topic count, language encoding). Features are standardized with StandardScaler ($\mu=0$, $\sigma=1$) and the target is log-transformed --- $\log(1+\text{stars})$ --- to handle the highly skewed star distribution.

We trained three models on an 80/20 train-test split: (1) \textbf{Linear Regression} as a baseline, (2) \textbf{SVR} with RBF kernel ($C=15$, $\varepsilon=0.1$), and (3) a \textbf{Neural Network} with 3 layers (64--32--1 units, ReLU, 0.2 dropout). The log-transformation was critical: raw star counts range from 497 to 502{,}119, causing gradient instability, whereas the log-transformed range is 6.21 to 13.13.

\subsection{Deployment and Production Serving}

After training, the best model (architecture and weights) is transferred to the Prod VM via SCP using a Git Hook, which then restarts the Docker containers automatically~\cite{qian2020orchestrating}. The Prod VM runs three Docker services: a Flask API (port 5100), a RabbitMQ broker, and one or more Celery workers. The worker loads the TensorFlow model in memory and handles two tasks: batch inference over all 2{,}000 repositories (\texttt{/predictions}) and model accuracy evaluation (\texttt{/accuracy}). Horizontal scaling is achieved by running \texttt{docker compose up -d --scale worker\_1=N}, which adds worker replicas that pull tasks from the shared RabbitMQ queue~\cite{hariri2018}.
